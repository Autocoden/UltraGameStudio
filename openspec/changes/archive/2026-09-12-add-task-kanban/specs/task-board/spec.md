## Purpose

任务看板(task-board)能力为 UltraGameStudio 提供一个 Autocode 风格的任务工作面:用户以「待办 / 进行中 / 已完成」三列卡片管理开发与资产生成任务,并可把任务一键送入智能终端由 agent 执行。看板数据按工作区隔离并本地持久化。

## ADDED Requirements

### Requirement: 左侧导航入口

应用左侧导航栏(rail)必须在「智能终端」入口上方提供「任务看板」入口;点击后主区域切换为任务看板视图,当前激活入口以强调色高亮。入口必须显示徽标,数值为当前工作区「进行中」列的卡片数;没有进行中卡片时不显示徽标。

#### Scenario: 入口位于智能终端上方
- **WHEN** 应用渲染左侧导航栏
- **THEN** 「任务看板」入口出现在「智能终端」入口之前(上方),且位于「资产」之前

#### Scenario: 徽标反映进行中数量
- **WHEN** 当前工作区有 2 张「进行中」卡片
- **THEN** 任务看板入口显示徽标 2;当所有卡片移出「进行中」后徽标消失

### Requirement: 三列看板

任务看板视图必须展示「待办」「进行中」「已完成」三列,列内卡片按加入该列的先后顺序排列。每张卡片显示标题;有备注时显示备注。列或看板为空时必须显示空态提示而非空白区域。

#### Scenario: 首次打开显示空看板
- **WHEN** 当前工作区从未创建过任务卡片时打开看板
- **THEN** 三列全部可见,各列显示空态提示,页面不报错

#### Scenario: 卡片内容呈现
- **WHEN** 一张卡片标题为「生成主菜单 UI」且备注为「参考 3 个候选方案」
- **THEN** 该卡片同时显示标题与备注文本

### Requirement: 卡片生命周期

用户必须能够在任意列底部新建卡片(输入标题后提交,新卡片出现在该列末尾),必须能够编辑已有卡片的标题与备注,必须能够删除卡片。新建卡片标题为空白(仅空白字符)时不得创建卡片。

#### Scenario: 在待办列新建卡片
- **WHEN** 用户在「待办」列输入「生成主菜单 UI」并提交
- **THEN** 「待办」列末尾出现标题为「生成主菜单 UI」的新卡片

#### Scenario: 空白标题被拒绝
- **WHEN** 用户提交仅含空白字符的标题
- **THEN** 不创建任何卡片

#### Scenario: 删除卡片
- **WHEN** 用户删除一张卡片
- **THEN** 该卡片从看板消失,且不再计入任何徽标或统计

### Requirement: 列间移动

用户必须能够把卡片在「待办」「进行中」「已完成」之间移动:支持把卡片拖拽到目标列,也支持不依赖拖拽的按钮方式(向左/向右移动)。卡片首次进入「已完成」时记录完成时间并在卡片上展示;移出「已完成」后清除完成时间。

#### Scenario: 拖拽移动
- **WHEN** 用户把「待办」列的一张卡片拖到「进行中」列
- **THEN** 卡片从「待办」消失并出现在「进行中」末尾,入口徽标随之 +1

#### Scenario: 按钮移动
- **WHEN** 用户点击一张卡片上的「下一列」按钮
- **THEN** 卡片移动到下一列(已完成之后无处可移时按钮不产生变化)

#### Scenario: 完成时间展示与清除
- **WHEN** 卡片被移动到「已完成」后再移回「进行中」
- **THEN** 进入「已完成」时卡片显示完成时间,移回后不再显示

### Requirement: 清空已完成

用户必须能够一键清空「已完成」列的全部卡片;清空操作只影响「已完成」列,不得动其他列。

#### Scenario: 清空已完成列
- **WHEN** 「已完成」列有 3 张卡片、「待办」列有 2 张,用户执行清空已完成
- **THEN** 「已完成」列变为空态,「待办」列的 2 张卡片保持不变

### Requirement: 工作区隔离与持久化

看板数据必须按工作区隔离:切换工作区后,看板展示并编辑的是该工作区自己的卡片集合。看板数据必须持久化到本地存储,应用刷新或重启后恢复;本地存储内容损坏时,应用必须回退为空看板并正常工作,不得崩溃。

#### Scenario: 切换工作区看到各自的看板
- **WHEN** 工作区 A 有卡片「A 任务」,工作区 B 有卡片「B 任务」,用户从 A 切换到 B
- **THEN** 看板只显示「B 任务」;切回 A 后只显示「A 任务」

#### Scenario: 重启后恢复
- **WHEN** 用户创建卡片后关闭并重新打开应用
- **THEN** 之前创建的卡片按原列恢复

#### Scenario: 存储损坏时回退
- **WHEN** 本地存储中的看板数据不是合法 JSON
- **THEN** 应用按空看板启动,后续新建/移动操作正常工作

### Requirement: 发送到智能终端

每张卡片必须提供「发送到智能终端」操作:把任务组装为提示词(含标题,有备注时含备注)写入智能终端的输入框草稿,并切换到智能终端视图。输入框已有草稿时,必须在保留原草稿内容的前提下追加,不得静默丢弃用户已输入的内容。

#### Scenario: 写入空草稿并切换视图
- **WHEN** 智能终端输入框为空,用户对卡片「生成主菜单 UI」(备注「参考 3 个候选方案」)执行发送到智能终端
- **THEN** 当前视图切换为智能终端,输入框草稿包含「生成主菜单 UI」和「参考 3 个候选方案」

#### Scenario: 保留已有草稿
- **WHEN** 智能终端输入框已有草稿「先审查现有 UI」,用户执行发送到智能终端
- **THEN** 输入框草稿同时包含原内容「先审查现有 UI」与任务提示词
