# task-board Specification

## Purpose
任务看板(task-board)能力为 UltraGameStudio 提供一个 Autocode 风格的任务工作面:用户以「待办 / 进行中 / 已完成」三列卡片管理开发与资产生成任务,并可把任务一键送入智能终端由 agent 执行。看板数据按工作区隔离并本地持久化。

## Requirements

### Requirement: 左侧导航入口

应用左侧导航栏(rail)必须在「智能终端」入口上方提供「任务看板」入口;点击后主区域切换为任务看板视图,当前激活入口以强调色高亮。入口必须显示徽标,数值为当前工作区「进行中」列的卡片数;没有进行中卡片时不显示徽标。

#### Scenario: 入口位于智能终端上方
- **WHEN** 应用渲染左侧导航栏
- **THEN** 「任务看板」入口出现在「智能终端」入口之前(上方),且位于「资产」之前

#### Scenario: 徽标反映进行中数量
- **WHEN** 当前工作区有 2 张「进行中」卡片
- **THEN** 任务看板入口显示徽标 2;当所有卡片移出「进行中」后徽标消失

### Requirement: 看板阶段

任务看板必须展示六个固定阶段列，顺序为：待规划（backlog）、队列（queue）、进行中（in_progress）、AI 审核（ai_review）、人工审核（human_review）、完成（done），与 Autocode 看板的列序一致。列内卡片按加入该列的先后顺序排列。每张卡片显示标题；有备注时显示备注；携带分类元数据时按 Autocode 规则显示徽章——分类、复杂度有值即显示，优先级仅高/紧急显示，影响仅高影响/关键影响显示。每列头必须以区别性配色标识阶段（backlog 中性、queue 蓝、in_progress 信息色、ai_review 琥珀、human_review 紫、done 绿）。列或看板为空时必须显示空态提示而非空白区域。

应用升级时若本地存有旧三阶段（待办/进行中/已完成）数据，必须自动映射到新阶段（待办→待规划、进行中→进行中、已完成→完成），不得丢失或拒载任何卡片。

#### Scenario: 六列全部可见
- **WHEN** 用户打开任务看板
- **THEN** 看板从左到右依次展示 待规划、队列、进行中、AI 审核、人工审核、完成 六列

#### Scenario: 首次打开显示空看板
- **WHEN** 当前工作区从未创建过任务卡片时打开看板
- **THEN** 六列全部可见，各列显示空态提示，页面不报错

#### Scenario: 卡片内容呈现
- **WHEN** 一张卡片标题为「生成主菜单 UI」、备注为「参考 3 个候选方案」、分类为「功能」、优先级为「紧急」
- **THEN** 该卡片显示标题、备注，以及「功能」「紧急」两枚徽章

#### Scenario: 低优先级不显示徽章
- **WHEN** 一张卡片的优先级为「低」、影响为「低影响」
- **THEN** 该卡片不显示优先级与影响徽章

#### Scenario: 旧三阶段数据迁移
- **WHEN** 本地存储中存在 v1 版本数据：待办列有卡片 A、进行中列有卡片 B、已完成列有卡片 C
- **THEN** 升级后打开看板，A 位于「待规划」、B 位于「进行中」、C 位于「完成」，三张卡片均无丢失

### Requirement: 卡片生命周期

用户必须能够通过所在列的新建弹窗创建卡片（提交后出现在该列末尾），必须能够通过编辑弹窗修改卡片的标题、备注与分类元数据（打开时预填当前值），必须能够删除卡片。新建与编辑时标题为空白（仅空白字符）的提交必须被拒绝。列底不再提供内联输入框。

#### Scenario: 在待办列新建卡片
- **WHEN** 用户在「待规划」列的新建弹窗中输入「生成主菜单 UI」并提交
- **THEN** 「待规划」列末尾出现标题为「生成主菜单 UI」的新卡片

#### Scenario: 空白标题被拒绝
- **WHEN** 用户在弹窗中提交仅含空白字符的标题
- **THEN** 不创建（或保存）任何卡片，弹窗保持打开等待修正

#### Scenario: 编辑预填并保存
- **WHEN** 用户对一张标题「旧标题」、备注「旧备注」、分类「功能」的卡片打开编辑弹窗，将其改为「新标题」「新备注」、分类「缺陷修复」并保存
- **THEN** 卡片以新标题、新备注与「缺陷修复」徽章呈现

#### Scenario: 删除卡片
- **WHEN** 用户删除一张卡片
- **THEN** 该卡片从看板消失，且不再计入任何徽标或统计

### Requirement: 列间移动

用户必须能够把卡片在六个阶段之间按列序移动（待规划 → 队列 → 进行中 → AI 审核 → 人工审核 → 完成）：支持把卡片拖拽到目标列，也支持不依赖拖拽的按钮方式（上一阶段/下一阶段）。卡片首次进入「完成」时记录完成时间并在卡片上展示；移出「完成」后清除完成时间。

#### Scenario: 拖拽移动
- **WHEN** 用户把「待规划」列的一张卡片拖到「进行中」列
- **THEN** 卡片从「待规划」消失并出现在「进行中」末尾，入口徽标随之 +1

#### Scenario: 按钮移动
- **WHEN** 用户连续点击一张卡片上的「下一阶段」按钮
- **THEN** 卡片沿 待规划 → 队列 → 进行中 → AI 审核 → 人工审核 → 完成 逐列右移；到达「完成」后按钮不再产生变化

#### Scenario: 完成时间展示与清除
- **WHEN** 卡片被移动到「完成」后再移回「人工审核」
- **THEN** 进入「完成」时卡片显示完成时间，移回后不再显示

### Requirement: 完成归档

「完成」列必须支持归档，归档保留数据而非删除：单张已完成卡片可被归档，列头提供「全部归档」一键归档所有未归档的已完成卡片。已归档卡片默认在「完成」列隐藏，开启「显示已归档」后以置灰样式列出并标注「已归档」，且可恢复回普通状态。已归档卡片不得计入列计数与任何统计，不得被拖拽或移动。其他列不受归档操作影响。

#### Scenario: 清空已完成列
- **WHEN** 「完成」列有 3 张未归档卡片、「待规划」列有 2 张，用户执行「全部归档」
- **THEN** 3 张卡片全部进入已归档状态并从默认视图隐藏(数据保留、可恢复显示),「待规划」列的 2 张卡片保持不变

#### Scenario: 归档单张卡片
- **WHEN** 用户对一张已完成卡片执行「归档」
- **THEN** 该卡片从默认视图隐藏，开启「显示已归档」后以置灰「已归档」样式可见

#### Scenario: 显示与恢复归档卡片
- **WHEN** 用户开启「显示已归档」并对一张已归档卡片执行「恢复」
- **THEN** 该卡片回到「完成」列普通状态，恢复计数与正常样式

#### Scenario: 归档不占统计
- **WHEN** 「完成」列有 2 张普通卡片与 3 张已归档卡片
- **THEN** 列计数显示 2;开启「显示已归档」后归档卡片可见但不计入该数值

### Requirement: 工作区隔离与持久化

看板数据必须按工作区隔离:切换工作区后,看板展示并编辑的是该工作区自己的卡片集合。看板数据必须持久化到本地存储,应用刷新或重启后恢复;本地存储内容损坏时,应用必须回退为空看板并正常工作,不得崩溃。

#### Scenario: 切换工作区看到各自的看板
- **WHEN** 工作区 A 有卡片「A 任务」,工作区 B 有卡片「B 任务」,用户从 A 切换到 B
- **THEN** 看板只显示「B 任务」;切回 A 后只显示「A 任务」

#### Scenario: 重启后恢复
- **WHEN** 用户创建卡片后关闭并重新打开应用
- **THEN** 之前创建的卡片按原列恢复

#### Scenario: 存储损坏时回退
- **WHEN** 本地存储中的看板数据不是合法 JSON
- **THEN** 应用按空看板启动,后续新建/移动操作正常工作

### Requirement: 新建任务弹窗

每个阶段列的列头必须提供新建入口（"+"按钮）；点击后弹出新建任务弹窗，且该列作为新卡片的初始阶段。弹窗必须包含：标题输入框（必填）、描述多行输入（可选）、以及四项可选分类下拉——分类（功能/缺陷修复/重构/文档/安全）、优先级（低/中/高/紧急）、复杂度（极低/小/中/大/复杂）、影响（低影响/中等影响/高影响/关键影响）。取消或按 Esc 关闭弹窗时不得创建任何卡片；提交后弹窗关闭，新卡片出现在触发列的末尾。标题为空白（仅空白字符）时提交必须被拒绝且弹窗保持打开。

#### Scenario: 从列头加号新建
- **WHEN** 用户点击「进行中」列头的"+"按钮，在弹窗中输入标题「生成主菜单 UI」并提交
- **THEN** 弹窗关闭，「进行中」列末尾出现标题为「生成主菜单 UI」的卡片

#### Scenario: 弹窗内填写分类信息
- **WHEN** 用户在弹窗中选择分类=功能、优先级=紧急后提交有效标题
- **THEN** 新卡片携带该分类与优先级信息

#### Scenario: 取消不创建
- **WHEN** 用户在弹窗中输入内容后点击取消（或按 Esc）
- **THEN** 弹窗关闭，看板不产生任何新卡片

### Requirement: 任务执行队列

看板必须提供任务执行队列：「队列」列中的任务由运行器按入队顺序自动拾取执行，无需用户逐个手动触发。同时执行的任务数必须受并行执行数限制（可在 1–4 之间调整，默认 1，设置持久化）。执行中的卡片必须显示「执行中」标记并提供「停止」操作；停止后该任务按失败处理（标注「手动停止」，落「人工审核」列）。

#### Scenario: 队列任务自动执行
- **WHEN** 「队列」列有 2 张卡片且当前没有任务在执行
- **THEN** 运行器自动拾取第一张执行，该卡片状态变为「进行中」并显示执行中标记

#### Scenario: 并行数限制
- **WHEN** 并行执行数为 1 且已有 1 个任务在执行，「队列」列还有 2 张卡片
- **THEN** 其余卡片保持在「队列」列等待，直到执行中的任务结束

#### Scenario: 停止执行中的任务
- **WHEN** 用户对一个执行中的任务点击「停止」
- **THEN** 该任务停止执行，标注失败原因「手动停止」，卡片落入「人工审核」列

### Requirement: 执行阶段与自动流转

任务执行必须由 agent 在当前工作区内直接完成（提示词包含任务标题、描述与分类信息），不经过聊天会话。执行完成后运行器必须自动发起一次 AI 审核（在工作区内核对任务是否完成）；审核通过的任务进入「人工审核」列并标记「待人工审核」，审核不通过或执行异常的任务同样进入「人工审核」列并标注失败原因。「人工审核」列的卡片必须提供「通过」（状态变为「完成」，标记「已完成」）与「重新执行」（回到「队列」列重新排队）操作。应用重启时，执行中的任务必须回退到「队列」列重新排队。

#### Scenario: 执行完成后进入人工审核
- **WHEN** 一个任务被拾取执行且 agent 完成工作、AI 审核通过
- **THEN** 卡片依次经过「进行中」「AI 审核」后落入「人工审核」列，显示「待人工审核」标记

#### Scenario: AI 审核不通过
- **WHEN** agent 执行结束但 AI 审核判定任务未完成
- **THEN** 卡片落入「人工审核」列并显示失败原因

#### Scenario: 人工通过验收
- **WHEN** 用户对「人工审核」列的一张卡片点击「通过」
- **THEN** 卡片状态变为「完成」，显示「已完成」标记

#### Scenario: 重新执行
- **WHEN** 用户对「人工审核」列的一张卡片点击「重新执行」
- **THEN** 卡片回到「队列」列末尾，运行器按队列规则重新拾取执行

#### Scenario: 重启后恢复
- **WHEN** 应用重启时有任务处于执行中状态
- **THEN** 该任务回退到「队列」列重新排队，不丢失、不悬挂在执行中状态
